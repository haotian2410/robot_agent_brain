## 发现的问题与修复

### 问题1: T02碰撞错误 (6/12失败)
**根因**: 父行T01在桌面中心放置棒球，阻挡了T02的left_back和center位置

**修复尝试**:
1. 创建固定fixture → catalog_revision不匹配
2. 使用center_empty run profile → 5/12通过，5个仍有几何约束问题

**结论**: T02的left_back和center位置存在真实的几何约束问题，超出简单的父行碰撞

### 问题2: T08.V04 "南侧"方向澄清错误
**根因**: Prompt模板只映射了角区的罗盘方向，没有映射相对移动的罗盘方向

**修复**: 在`task_understanding_clean_v3.txt`第485行后添加罗盘方向映射：
```
- 相对移动的罗盘方向映射：东侧/东边=`right_of`，西侧/西边=`left_of`，南侧/南边=`behind`，北侧/北边=`front_of`。这与桌面角区映射一致：右=东，左=西，后=南，前=北。
```

**状态**: ✅ 已修复，Brain服务已重启

### 问题3: T11替换资产全部失败 (5/5)
**根因1**: V01-V04 - Qwen要求钢笔款式澄清（橙色vs黑色）
**根因2**: V05 - 缺少`replacement_entity`字段

**修复1**: 更新Prompt替换部分，明确当用户指定语义名称时不要询问款式澄清
```
如果用户没有明确新对象的语义名称（例如只说"替换一下"而不说替换成什么），返回
`clarification_required`，不要猜测替换模型。但如果用户明确给出了语义名称（例如"钢笔"），
即使目录中有多个同名不同款式的变体（例如橙色钢笔和黑色钢笔），也直接选择该语义名称，
不要因为款式差异而澄清。Python 会按配置的默认资产完成选择。
```

**修复2**: 在`qwen_http.py`中添加`_repair_live_replace_entity`函数，为实时turn填充缺失的`replacement_entity`

**状态**: ✅ 已修复，Brain服务已重启

### 问题4: T15多步顺序测试阻塞 (3/4)
**根因**:
- V01: 钢笔款式澄清（同T11）
- V02: Qwen混淆"生成一个钢笔，再把它的颜色设为蓝色"
- V03: Qwen混淆"生成一个钢笔，再让它向右移动五厘米"，误判为机器人任务

**修复**: 在Prompt第8节添加多步操作澄清：
```
用户说"生成一个苹果，再让它向右移动五厘米"时，两个操作都是场景编辑：第一个是 `add`，第二个是 `translate`。只要用户给出了明确的距离（如"五厘米""0.05米""5cm"），就是场景编辑的平移操作，不是机器人任务。机器人任务不会包含具体距离数值。

用户说"增加一个苹果，然后把它改成蓝色"时，两个操作也都是场景编辑：第一个是 `add`，第二个是 `update_properties`。多步操作按顺序输出到同一个 `scene_edit.operations` 数组中。
```

**状态**: ✅ 已修复，Brain服务已重启，待验证
