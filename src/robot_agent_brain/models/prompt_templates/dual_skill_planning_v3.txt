context.hold_constraints 是不可省略的用户时序约束。hold_during_operation 要求 holder_arm 在 while_operation 的每个阶段 null、稳定保持物体（及给定区域）。hold_until_operation 要求 holder_operation 的 move 到 placement_region 先独立完成，再执行 while_operation 的全部技能，最后才执行 holder_operation 的 release。不能同阶段读取到位效果，不能提前释放。每个高层操作仍须输出完整技能序列；无需自行输出 conditions，Python 会生成并验证它们。未给保持要求时不要新增。不能用 hold/wait/pour 等未注册技能替代 null。
同一阶段动作基于相同前态，全部成功后才能进入下一阶段。null 保持该臂现有状态，不释放或回零。
动作仅包含 operation_id、skill、target_role、reference_role、region；角色来自该 operation 的 valid_roles。
不得输出真实物体ID、机器人实例、坐标、关节、轨迹、距离、conditions或执行结果。
保持每个 operation 的 arm、对象角色和目标，不增删操作。depends_on 必须完整完成后开始依赖操作。
仅相同且非空 parallel_group 的操作可放同一阶段。parallel_required 的同组操作必须从同一阶段开始；不能假称满足同时而串行。
每臂保持自己的持物状态，不能抓取已由另一臂持有的对象，不能用同阶段另一动作尚未完成的定位或移动结果。
grasp：locate target → move target/grasp_region → grasp target。
pick_and_place：未持 source 时 locate source → move source/grasp_region → grasp source；然后 locate destination → move destination（reference_role=source，region=placement_region）→ release source（reference_role=destination，region=placement_region）。已持 source 时不再抓取。
move：空夹爪时先 locate/move/grasp 目标，再 move 目标（region=null，由 Python 提供用户距离），最后 release 目标；原本已持目标时仅 move，不擅自释放。
每个 operation 的 initially_holds_actor 与 required_final_gripper 是确定性的任务完成约束。required_final_gripper=empty 时，若本操作抓取了目标，必须包含 release；不能在移动后直接填 null。输出前逐臂检查这一终态。
例如左臂 pick_and_place、右臂从空夹爪 move：前三阶段两边 locate/move抓取区/grasp；第四阶段左locate destination、右move target且region=null；第五阶段左move destination/placement_region、右release target且reference_role=null/region=null；第六阶段左release source/reference_role=destination/placement_region、右null。
release：必须已持目标。locate：只定位目标。
